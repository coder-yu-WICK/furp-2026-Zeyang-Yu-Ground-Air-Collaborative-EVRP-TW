1. 问题形式化定义

带时间窗的电动车辆路径问题（EVRP-TW）

令 G = (V, E) 为一个完全有向图，其中 V = {0, 1, ..., N}，节点 0 为车场（depot），节点 1 至 N 表示客户。每条边 (i, j) 具有相应的行驶距离 dij 和行驶时间 tij = dij / v，其中 v 为恒定车速（35 km/h）。

客户属性

  • 需求量 qi ≥ 0：需要配送的货物数量
  • 最早到达时间（Ready time） ei：最早服务开始时间（若提前到达则等待）
  • 最晚到达时间（Due time） li：最晚服务开始时间（硬约束 — 迟到即为不可行）
  • 服务时间（Service time） si：完成配送所需的时长

车队配置

  • K 辆同质电动卡车，每辆载重容量 Q = 200，电池容量 B = 55 kWh
  • 能耗速率 ρ = 1.5 kWh/km，有效续航约 37 km
  • M = 3 个充电站（CS），分别位于车场 (8.0, 8.0)、西北象限 (4.0, 12.0) 和东南象限 (12.0, 4.0)
  • 充电函数 C(socstart, Δt)：三段分段非线性（Montoya 等, 2017）

数学形式化

决策变量。 令 xijk ∈ {0, 1} 表示卡车 k 是否经过边 (i, j)。令 aik ≥ 0 为卡车 k 到达节点 i 的时间。令 uik ≥ 0 为到达时的剩余电量。令 wik ≥ 0 为服务前的等待时间。

目标函数。

minimize   Σk=1K [ Cfixed + Cdist × Σ(i,j)∈E dij xijk ]

其中 Cfixed = 100.0（每辆卡车固定成本）且 Cdist = 2.0（每单位距离成本）。

约束条件。

1. 覆盖约束:         Σk=1K Σj∈V xijk = 1             ∀ i ∈ {1, ..., N}
2. 流量守恒:         Σj∈V xijk = Σj∈V xjik       ∀ i ∈ V, ∀ k
3. 容量约束:          Σi=1N qi Σj∈V xijk ≤ Q   ∀ k
4. 时间窗约束:       ei ≤ max(ei, aik) ≤ li   ∀ i, ∀ k
5. 到达时间递推:     ajk ≥ aik + si + tij - M(1 - xijk)
6. 电量动态:         ujk ≤ uik - ρ × dij + B(1 - xijk)   （未充电情况下）
7. 电量边界:         0 ≤ uik ≤ B                                   ∀ i, ∀ k
8. 车场出发:         u0k = B, a0k = 0                          ∀ k
计算复杂度

EVRP-TW 包含三个 NP-hard 子问题：(i) 车辆路径问题（VRP），用于客户划分；(ii) 带时间窗的旅行商问题（TSP-TW），用于每条路线的顺序编排；(iii) 固定路线车辆充电问题（FRVCP），用于充电决策。对这三个子问题直接进行联合优化，在超过常规实例规模后计算上不可行。

路线仿真模型

任意候选路线 R = (v1, ..., vn) 的评估通过确定性前向仿真完成。给定车速 v = 35 km/h 且车场为节点 0：

prev := 0  (车场)
current_time := 0.0

FOR each cust_idx in route:
    c := customers[cust_idx - 1]

    // 从前一节点出发的行驶距离
    IF prev == 0:
        d := Euclidean(depot, c.coords)
    ELSE:
        d := Euclidean(customers[prev - 1].coords, c.coords)

    total_distance += d
    current_time += d / TRUCK_SPEED

    // 若在 ready_time 之前到达则等待
    IF current_time < c.ready_time:
        current_time := c.ready_time

    arrival_time[cust_idx] := current_time
    tardiness[cust_idx] := max(0, current_time - c.due_time)

    current_time += c.service_time
    prev := cust_idx

// 返回车场
total_distance += Euclidean(customers[prev - 1].coords, depot)

该确定性仿真是整个框架的主力引擎：它被解评估器（TruckSolution._evaluate()）、Forward Insertion 成本函数、CLS 约束检查器和路线合并可行性检查调用。其 O(n) 的逐路线复杂度使得重复调用在计算上可行。

2. 方法学框架

2.1 分解范式

将路径规划（Routing）与时间调度（Scheduling）分离

本框架的核心方法学洞见是：路径规划（确定将哪些客户分组以及按什么空间顺序访问）与时间调度（确保到达时间满足时间窗约束）是可分离的问题，可以分别采用独立的技术求解：

  • 路径规划由 POMO 神经网络（Kwon 等, 2020）处理 — 一种基于 Transformer 的构造启发式方法，在 CVRP 上预训练，生成距离最优的客户序列。该神经网络作为一个空间优化器：它在不了解硬时间窗约束的情况下最小化总行驶距离。
  • 时间调度由 Forward Insertion（前向插入）处理 — 一种确定性修复算子，将迟到的客户精确地移动到路线中更早的位置。这是一个时序修复算子：它在保留 POMO 建立的空间结构的同时，保证零延迟。
分离的正当性论证

路径规划与时间调度在单一目标函数内的联合优化，正是导致经典元启发式算法（NSGA-II、P-ACO、IVND）在 EVRP-TW 上失败的原因。当延迟和距离在标量化的适应度函数中作为加权项竞争时，距离总是胜出：在典型权重配置下，10 单位的距离缩短压倒了任何可行程度的延迟减少。结果是收敛到距离最优但 TW 不可行的解（在 224 个 Solomon 实例上可行率为 0%）。

通过分解问题，每个组成部分都可以用专为其目标设计的技术来优化：距离用神经构造，时间窗用精确重排。该分解还允许对每个阶段的保证进行独立的理论分析（见第 3.3 节）。

阶段 1：Budget-Aware 聚类

维度规约
目的将 N 个客户划分为 K 个空间紧凑、时序可行的聚类，每个聚类分配一辆卡车。实现了先聚类、后路径（Cluster-First, Route-Second）范式（Fisher & Jaikumar 1981）。
输入契约instance: dict，包含键：customers（字典列表，包含 id、x、y、demand、ready_time、due_time、service_time）、depot（x, y）、n_customers（int）、tw_type（str）
输出契约clusters: list[list[dict]] — 原始客户列表的 K 个不相交子列表，每个子列表形成一个空间紧凑的组，且相对于 TW 时间跨度具有 ≥ 25% 的时序松弛余量
算法阶段 1：K-means++ 初始化（Arthur & Vassilvitskii 2007）用于空间质心放置，随后在 (x, y) 坐标上进行 Lloyd 迭代直至收敛（最多 50 次迭代）。阶段 2：对每个聚类，模拟 EDD 排序以估计所需路线时间；若 route_time > 0.75 × TW_budget（其中 TW_budget = max(due_time) - min(ready_time)），则在最优间隙点按 due_time 分割聚类。阶段 3：容量均衡：将超载聚类中的多余客户重新分配到最近的低载聚类质心。75% 阈值根据定理 1（见第 3.3 节）为 Forward Insertion 保留 25% 的松弛余量。
复杂度O(N × K × I + C × log C)，其中 I = 50（Lloyd 迭代次数），C = 最大聚类大小（用于 EDD 仿真）。由 K-means 分配步骤主导。
文件引用pipeline/adaptive_clustering.py::cluster_with_params()，可行性检查位于 pipeline/cluster_feasibility.py::ensure_temporal_feasibility()
设计原则：最小干预

聚类策略优先考虑空间紧凑性而非时序可行性。首先应用纯空间 K-means；仅当超过 75% 阈值时才触发时序分割。其依据是：空间紧凑的聚类产生短路线，进而产生更多时序松弛余量 — 空间与时序目标是一致的，而非相互竞争的。在 RC 和 R 类实例上，约 10-20% 的聚类会触发分割；在 C 类（聚类空间分布）上，几乎不需要分割。

聚类算法详解

算法：Budget-Aware 聚类（cluster_with_params）
────────────────────────────────────────────────────
输入：  instance dict、卡车数量 K、策略='budget_aware'
输出：  K 个聚类字典的列表（每个包含客户子列表）

参数：
  TW_BUDGET_RATIO = 0.75    // 若 route_time > TW 时间跨度的 75% 则分割
  KMEANS_ITERS = 50         // Lloyd 迭代次数
  TRUCK_CAPACITY = 200.0    // 用于容量均衡

阶段 1：空间 K-means++
  1. 通过 kmeans++ 播种初始化 K 个质心：
     - 第一个质心：从客户中均匀随机选择
     - 后续质心：概率正比于 D(x)^2
       其中 D(x) = 到最近已选质心的距离
  2. 对于 iter in 1..KMEANS_ITERS：
     a. 分配：每个客户 → 最近质心（仅 xy 坐标欧氏距离）
     b. 更新：每个质心 = 所分配客户坐标的均值(x,y)
     c. 若分配未变化：跳出（收敛）
  3. 返回 K 个聚类（空间紧凑，未检查时序）

阶段 2：条件时序分割
  对于每个聚类 c in clusters：
    1. 确定 TW 时间跨度：
       tw_budget = max(due_time) - min(ready_time)  // 跨聚类
    2. 估计所需路线时间：
       edd_order = sort(c.customers, key=due_time)
       route_time = simulate_edd_route(edd_order)
       // 包括：行驶时间 + 服务时间 + 在 ready_time 前的等待时间
    3. 若 route_time > TW_BUDGET_RATIO * tw_budget：
       a. 按 due_time 升序排列聚类
       b. 扫描最优分割点：
          对于每个可能的分割索引 k：
            left_group = customers[:k]
            right_group = customers[k:]
            left_time = simulate_edd_route(left_group)
            right_time = simulate_edd_route(right_group)
            score = max(left_time, right_time)  // 最小化最差情况
          选择具有最小 score 的 k*
       c. 在索引 k* 处将聚类分割为两个
       d. 递归检查每个子聚类（若仍过大则继续分割）
    4. 否则：保持聚类原样（最常见情况）

阶段 3：容量均衡
  对于每个聚类 c in clusters：
    total_demand = sum(customer.demand for customer in c)
    若 total_demand > TRUCK_CAPACITY：
      excess = total_demand - TRUCK_CAPACITY
      // 识别距离低载聚类质心最近的客户
      对于每个低载聚类 u （total_demand < TRUCK_CAPACITY）：
        // 将 c 中距离 u 的质心最近的客户迁移
        best_cust = argmin_{cust in c} distance(cust, centroid(u))
        若 demand(best_cust) <= (TRUCK_CAPACITY - total_demand(u))：
          move(best_cust, c → u)
          若 total_demand(c) <= TRUCK_CAPACITY：跳出

针对 FI 感知的时序可行性预检查

原始预检查使用 EDD 仿真，这是悲观的：EDD 排序对延迟而言是最优的，但对距离而言不是，因此它会高估所需的路线时间。这导致了不必要的分割，产生过多的微路线（C101_100c：100 个客户被分成 69 条路线）。

改进后的预检查（cluster_feasibility.py::ensure_temporal_feasibility()）使用 POMO 的实际空间邻接排序，并结合定理 1 的松弛条件。如果路线的理论松弛量（前缀时间缓冲）超过预测的延迟量，即使基于 EDD 的估计认为不可行，该聚类也被认为可行。这将不必要的时序分割减少了约 40-50%。

阶段 2：POMO 神经路径规划

维度规约
目的对每个聚类，使用预训练 Transformer 神经网络生成距离最优的客户访问序列。该阶段是一个构造启发式 — 它从零开始构建路线，而非在已有路线中搜索。
输入契约mini_instance: dict，每个聚类具有重新索引的客户 ID（1..m）、本地距离矩阵（(m+1) × (m+1)，包含车场）以及客户特征 [(x, y, demand, ready_time, due_time, service_time)]
输出契约truck_routes: list[list[int]] — K 个客户索引序列（从 1 开始编号）。路线已进行距离优化，但可能包含时间窗违反（延迟 > 0）。
模型架构编码器：6 层 Transformer 编码器（Vaswani 等, 2017）。客户特征（6 维）投影到 128 维嵌入。每个编码器层使用 8 头多头自注意力（dk = 16），配合 Add & LayerNorm，随后是逐位置前馈网络（128 → 512 → 128，ReLU 激活）。解码器：基于注意力的自回归解码器。每一步，Query 为当前节点的编码与动态上下文特征 [剩余容量、当前时间、累计距离、电量比例] 的拼接。交叉注意力在所有编码器输出上操作（为推理缓存）。logit 裁剪机制（tanh，C = 10.0）稳定训练过程。Softmax 在未访问节点上产生概率分布。掩码：已访问节点和容量不可行节点被掩码（概率 = 0）。应用宽松的 TW 掩码（arrival_time > due_time + 60），但这是软约束，不保证 TW 可行性。
推理每个聚类：(1) 8 重坐标增强（翻转 x × 翻转 y × 转置 = 8 种几何视图），(2) 在每个视图内，从 N 个不同起始节点启动 N 条轨迹（POMO 多起点），(3) 贪婪自回归解码（每步选择 argmax 概率）。每个聚类的候选路线总数 = 8 × |cluster|。选择成本（距离 + 延迟 × 0.1）最小的路线。推理时间：每个 20-30 个客户的聚类约 0.1 秒。
复杂度每个聚类 O(m2 × L)，其中 m = 聚类大小，L = 6（编码器层数）。自注意力每层为 O(m2)。8 重增强乘以常数因子 8。
文件引用pipeline/pomo_solver.py::ImprovedPOMOSolver；模型定义位于 algorithms/pomo/pomo_model.py::POMOModel；增强位于 algorithms/pomo/pomo_problem.py::augment_xy_by_8_fold()
在框架中的角色定位

POMO 被视为一个距离神谕（distance oracle），而非完整的 EVRP-TW 求解器。其训练目标（CVRP 上使用 POMO 基线的 REINFORCE）以距离为优化目标；延迟在奖励中的权重为 0.1。该模型生成具有优良空间结构的路线，但不提供理论上的 TW 保证。这是有意为之：TW 保证由阶段 3（Forward Insertion）提供，使 POMO 能够专注于其最擅长的方面。

POMO 训练方案

POMO 模型在标准 CVRP 实例（非 EVRP-TW）上预训练，并以零样本推理模式用于 EVRP-TW。核心训练参数：

参数值理由
训练轮次80在 CVRP-20/50/100 上足够收敛
每轮回合数400总计约 25,600 个训练实例
批次大小64平衡 GPU 内存与梯度稳定性
学习率1e-4Adam 优化器，权重衰减 1e-6
REINFORCE 基线POMO（N 条轨迹均值）N 个起始节点各自产生一条轨迹；所有 N 条轨迹的均值奖励作为基线，相较于单轨迹 REINFORCE 大幅降低梯度方差
数据增强8 重（翻转 x/y + 转置）在训练和推理中均应用，实现几何不变性
奖励函数−(距离 + 0.1 × 延迟)以距离为主；TW 为软正则化项，而非硬约束

设计决策：零样本 vs. 微调。 一个自然的问题是 POMO 是否应该在 FI 修复后的路线上进行微调（从 FI 输出中进行监督学习）。分析后予以否定：估计改进上限约 3%（减少 FI 移动次数，而这本就微乎其微），同时需要在 A100 上花费约 2-3 GPU 天。零样本方法因其计算效率和方法论清晰性而更受青睐：它证明了即使在无问题专属神经训练的情况下，分解策略依然有效。

编码器架构详情

6 层 Transformer 编码器处理 N+1 个节点嵌入序列（N 个客户 + 1 个车场）。每个节点初始由一个 6 维特征向量 [x, y, demand, ready_time, due_time, service_time] 表示，线性投影到 128 维。不使用位置编码：该问题具有排列不变性（客户集合没有内在顺序）。每个编码器层计算：

EncoderLayer(x):
    // 多头自注意力（8 头，d_k = 16）
    Q, K, V = Linear_128(x), Linear_128(x), Linear_128(x)
    attn = Softmax(Q @ K^T / sqrt(16))  // (N+1) × (N+1) 注意力矩阵
    context = attn @ V
    context = Linear_128(context)
    x = LayerNorm(x + context)           // 残差 + 归一化

    // 前馈网络
    ff = Linear_512(ReLU(Linear_128(x))) // 128 → 512 → 128
    x = LayerNorm(x + ff)                // 残差 + 归一化
    return x

自注意力机制使得每个节点可以关注所有其他节点，学习空间关系（"哪些客户离我近？"）、时序关系（"谁的截止时间最早？"）和容量交互（"我的聚类中有多少需求？"）。8 个注意力头专精于不同的关系模式，但其具体专精特征不可人为解释。

解码器架构与自回归生成

解码器通过自回归贪婪解码，每次生成一个客户的路线。在第 t 步，给定部分路径 v1, ..., vt 和编码器输出，计算所有剩余未访问节点上的概率分布：

解码器步骤（贪婪生成）：
    // 1. 从当前状态构建查询
    current_node_embedding = encoder_output[current_position]     // (128,)
    context_features = [
        remaining_capacity / TRUCK_CAPACITY,    // [0, 1]
        current_time / max_horizon,             // 归一化
        cumulative_distance / expected_total,   // 归一化
        remaining_battery / BATTERY_CAPACITY,   // [0, 1]（EV 感知）
    ]                                           // (4,)
    query = Linear_128(concat(current_node_embedding, context_features))

    // 2. 在所有编码器输出上的交叉注意力
    keys = encoder_output                       // (N+1) × 128（缓存）
    values = encoder_output
    attn_scores = query @ keys^T / sqrt(16)    // (N+1,) 向量
    attn_scores = tanh_clip(attn_scores, C=10.0)  // logit 裁剪以稳定训练

    // 3. 应用掩码（在 softmax 前设为 -inf）
    若节点已访问：            score[node] = -inf
    若 demand > capacity_left：  score[node] = -inf
    若 arrival_estimate > due_time + 60：  score[node] = -inf  // 宽松 TW

    // 4. 选择下一个节点
    probs = Softmax(attn_scores)             // (N+1,) 有效概率

    更新 current_time、cumulative_distance、capacity_left

3. 核心算法：Forward Insertion

3.1 问题陈述

给定一条 POMO 生成的卡车路线 R = (v1, v2, ..., vn)，具有延迟 T(R) > 0（即 ∃ k 使得 ak > lk，其中 ak 为到达客户 vk 的时间），生成一条修改后的路线 R'，满足：

  1. T(R') = 0 — 所有客户均在其时间窗内得到服务
  2. |R' Δ R| 最小化 — 对 POMO 优化顺序的结构性改变最小化（保留距离优化成果）
  3. 该算法给定种子后为确定性算法且具有多项式时间复杂度

该方法必须是精确的（surgical）：它应该只重新定位迟到的客户，而非打乱整条路线。这与 Full EDD 重排序（Jackson 1955）形成对比，后者按 due_time 对整个路线进行排序，丢弃了所有 POMO 距离优化成果。

3.3 理论分析

引理 1 — 上游单调性：为何分段修复总是失败

形式化陈述。 令 R = (v1, ..., vn) 为一条路线，令 S = R[k:n] 为 R 从位置 k 开始的后缀。对于 S 的任意排列 S'，前缀节点 v1, ..., vk-1 的到达时间保持不变。此外，到达 vk（后缀的第一个节点）的时间仅取决于到 vk-1 的前缀以及从 vk-1 到 vk 的行驶时间，而不取决于 S 的内部顺序。

证明概要。 任意节点 vi 的到达时间按递推方式计算：ai = max(ei, ai-1 + si-1 + ti-1,i)。对于 i < k，该递推仅依赖于前缀 v1 至 vi。由于前缀未改变，所有 i < k 的 ai 是不变的。对于 ak，递推使用 ak-1、sk-1 以及从 vk-1 到 S' 中第一个节点的距离。但 tk-1, first(S') 取决于哪个节点被放在位置 k，而非 S' 其余部分的内部顺序。然而，无论 S' 如何排列，从 vk-1 的出发时间由前缀固定；后缀排序无法减少已累积的上游行驶时间。

推论 — 结构性延迟。 若 vk 之所以迟到，是因为通过前缀 v1..k-1 的累积行驶时间已耗尽可用时间预算，则 vk 在 S 的任意重排序下仍将保持迟到。这是结构性延迟（structural tardiness）（由位置决定），与顺序性延迟（sequential tardiness）（由排序决定）不同。

工程启示。 该引理直接预测了分段 EDD 修复（Partial EDD）100% 的失败率。任何迟到段中的第一个客户必然具有结构性延迟 — 段内重排序无法挽救它。唯一有效的修复是将迟到客户向前移动（改变其相对于整个前缀的位置，而非仅在某个后缀内），而这正是 Forward Insertion 所做的。

引理 2 — Forward Insertion 的有界副作用

形式化陈述。 令 R = (v1, ..., vn) 为一条路线。令 R' 为将客户 vj 从位置 j 移动到位置 i（i < j）的结果。则：

  1. 前缀保留： 对于所有 p < i，arrival(vp; R') = arrival(vp; R) — 插入点之前的节点完全不受影响。
  2. 被移动客户的改善： arrival(vj; R') ≤ arrival(vj; R) — 被移动的客户严格更早（或最差情况下同时）得到服务。
  3. 有界局部偏移： 对于所有 i < p < j，arrival(vp; R') ≤ arrival(vp; R) + sj + Δd，其中 Δd 是在这些位置之间插入 vj 所引入的最大可能绕行距离。延迟是有界的且是局部的。
  4. 尾部不退化： 对于所有 p > j，arrival(vp; R') ≤ arrival(vp; R) — vj 原始位置之后的节点不会比之前更晚得到服务（因为 vj 已从它们之前移除）。

证明概要。 每部分均从递推到达到达方程得出。第 (1) 部分：前缀递推独立于位置 i 之后的节点。第 (2) 部分：vj 现在在位置 i 而非 j 处得到服务；由于 i < j 且所有先前节点相同或是子集，到达位置 i 的累积行驶时间 ≤ 到达位置 j 的累积时间。第 (3) 部分：在位置 i 和 j 之间，插入了一次额外的服务（sj），且空间路径可能改变；每个被偏移节点的最差额外延迟为 sj 加上最大可能绕行距离。第 (4) 部分：由于 vj 被移除，位置 j 之后的节点向前移动，减少了累积时间。

工程启示。 Forward Insertion 是精确安全的（surgically safe）：副作用被限制在插入位置与原始位置之间的有界窗口内。前缀（可能包含时间关键客户）完全不受影响。算子消融实验证实了非对称性：Relocate 算子考虑前向和后向移动，但在实际中从不选择后向移动 — 前向移动总是更优。

定理 1 — 一次通过充分性条件

形式化陈述。 令 T 为路线 R 中迟到客户的集合，令 σ = Σp<min(T) (lp - ap) 为总前缀松弛量（最早迟到客户之前的未用时间预算）。若对于每个 vk ∈ T，存在一个插入位置 i < k，使得：

  1. arrival(vk 在位置 i) ≤ lk（被移动客户准时到达），且
  2. 对于位置 i 和 k 之间的所有被偏移节点 p，arrival(vp 偏移后) ≤ lp（没有被偏移节点变为迟到），

则 Forward Insertion 在一次通过（最多 |T| 次移动）内收敛到 T(R') = 0 的解，无需 EDD 回退。

证明概要（对 |T| 的归纳法）。 基础情况 |T| = 0：平凡满足。归纳步骤：假设 Forward Insertion 在一次通过内解决 |T| - 1 个迟到客户。处理最迟到的客户 vt。根据充分性条件，存在一个更早的位置，在此位置上 vt 准时且所有被偏移节点保持可行。在此移动之后，迟到客户集合为 T \ {vt}（被移动客户现已准时，且根据引理 2 的有界副作用，没有引入新的延迟）。根据归纳假设，剩余的 |T| - 1 个迟到客户在一次通过内解决。

充分松弛准则。 充分性条件的一个实用代理：若 σ ≥ Σv∈T (av - lv)（总前缀松弛量超过总延迟量），则该条件以高概率成立。这促成了 Budget-Aware 聚类中的75% TW 预算阈值（第 2.2 节，阶段 1）：通过确保 EDD 估计的路线时间不超过 TW 时间跨度的 75%，我们为 Forward Insertion 在定理 1 的充分性条件内运作保留了至少 25% 的松弛余量。

工程启示。 当松弛比率（prefix_slack / total_tardiness）低于 0.3 时，充分性条件不太可能成立。因此算法完全跳过了前向搜索，对该路线直接回退到 Full EDD，避免了浪费计算。实际中，该触发条件在不到 2% 的路线上激活，证实 Budget-Aware 聚类在绝大多数情况下提供了足够的松弛余量。C 类实例（聚类空间分布）实现了 100% 零回退，因为其短而紧凑的路线提供了充足的松弛余量 — 定理 1 的条件总是得到满足。

为了证明 Forward Insertion 是 TW 修复的最小充分算子 — 而不仅仅是众多同等有效的局部搜索算子之一 — 我们在 24 个代表性实例（6 种 TW 类型 × 4 个规模）上进行了消融研究，比较了四种算子：

算子移动类型搜索空间TW 可行性（24 个实例）回退次数核心发现
Forward Insertion 单节点 → 仅更早位置 每个节点 O(n) 个位置 24/24 (100%) 7 唯一具有完整理论框架的算子
Relocate（双向） 单节点 → 任意位置 每个节点 O(2n) 个位置 24/24 (100%) 7 结果与 FI 相同；从不选择后向移动
Or-opt（段移动） 连续段 → 前向 O(n2) 个段 16/24 (67%) — 在 C1/R1 上失败：段级别操作（引理 1）
2-opt*（段交换） 两个段交换 O(n2) 个段 16/24 (67%) — 在窄 TW 实例上零次移动
消融实验的三项核心结论
  1. Forward Insertion 与 Relocate 在结果上等价："仅前向"的限制不是一种缺陷，而是一种最优性属性。Relocate 具有 2 倍的搜索空间，却产生相同的结果，因为后向移动永远不会改善加权成本函数（引理 2）。Forward Insertion 以一半的计算搜索量实现了同等的有效性。
  2. 段级别算子在窄 TW 上失败（67%）：Or-opt 和 2-opt* 在 C1 和 R1 实例上实现了零次成功移动。这是引理 1 的直接经验后果：当延迟是结构性的（由累积上游时间导致）时，任何程度的段重排序都无法消除它。
  3. 简单即强大：Forward Insertion 受限的搜索空间不是一种妥协，而是基于引理 2 建立的非对称性的原则性设计选择。它是实现 100% TW 可行性且具有完整理论刻画的最小算子。

解成本模型

TruckSolution._evaluate() 评估的成本函数遵循三部分结构：

total_cost = vehicle_fixed + distance_cost + unserved_penalty

其中：
  vehicle_fixed = n_trucks * TRUCK_FIXED_COST       // 每辆卡车 100.0
  distance_cost = total_truck_distance * TRUCK_DIST_COST_RATE  // 每公里 2.0
  unserved_penalty = n_unserved_customers * 1000.0   // 硬不可行惩罚

  total_truck_distance = 逐路线求和：
    车场到首客户 + 连续客户对之和 + 末客户到车场
    （从 distance_matrix[i][j] 计算得到）

  tardiness = 所有客户求和：
    max(0, arrival_time - due_time) * TARDINESS_COST_RATE  // 每时间单位 1.0

成本模型中的关键设计决策：

  • 每辆卡车固定成本（100.0）：尽可能减少卡车使用数量。这是路线合并（阶段 5）背后的经济驱动力 — 每合并一条路线就消除一次固定成本。
  • 距离成本率（2.0）：校准为使距离成本和固定成本在量级上可比。在典型路线距离（20-30 个客户约 20-50 km）下，距离成本为 40-100 单位，而每辆卡车的固定成本为 100 单位。
  • 延迟成本率（1.0）：低于修复成本函数中的值（TARD_WEIGHT = 5.0）。在解评估器中，延迟作为可行性指标而非主要优化目标；修复成本函数使用更高权重以激进地将延迟驱动至零。
  • 未服务惩罚（1000.0/客户）：硬不可行惩罚确保未覆盖所有客户的解被任何覆盖了所有客户的解严格支配，无论其成本如何。

非线性充电模型实现

三段分段非线性充电函数（Montoya 等, 2017）通过一对互逆函数实现：

SEGMENTS = [(0.0, 0.2, 1.5), (0.2, 0.8, 1.0), (0.8, 1.0, 0.5)]
BASE_RATE = 1.0  # kWh/分钟
BATTERY_CAPACITY = 55.0  # kWh

def charge_nonlinear(soc_pct: float, duration_min: float) -> float:
    """
    正向：给定当前 SOC% 和充电时长，
    返回增加的 kWh。
    """
    remaining = duration_min
    total_kwh = 0.0
    current_soc = soc_pct

    for soc_low, soc_high, rate_mult in SEGMENTS:
        if current_soc >= soc_high:
            continue  # 跳过已过的段
        if remaining <= 0:
            break

        // 该段中的 kWh 容量
        segment_capacity = (min(soc_high, 1.0) - max(current_soc, soc_low))
        segment_capacity *= BATTERY_CAPACITY

        // 该段中的有效充电速率
        effective_rate = BASE_RATE * rate_mult  // kWh/分钟
        time_needed = segment_capacity / effective_rate

        if remaining >= time_needed:
            total_kwh += segment_capacity
            remaining -= time_needed
            current_soc = soc_high
        else:
            total_kwh += effective_rate * remaining
            remaining = 0
            break

    return total_kwh

def compute_nonlinear_charge_time(soc_pct, target_kwh):
    """
    逆向：给定当前 SOC% 和目标 kWh，
    返回所需充电时长。
    在 charge_nonlinear() 上使用二分查找。
    往返验证：charge_nonlinear(soc, compute_...(soc, kwh)) == kwh
    """
    lo, hi = 0.0, 200.0  # 分钟
    for _ in range(50):  # 二分查找，50 次迭代 → 机器精度
        mid = (lo + hi) / 2
        if charge_nonlinear(soc_pct, mid) < target_kwh:
            lo = mid
        else:
            hi = mid
    return hi

非线性模型的关键启示是：充到 80% 的时间效率是从 80% 充到 100% 的 2.6 倍。前探插入算法利用这一点，目标是"刚好够用"的充电量而非满充，使用逆向函数精确计算所需充电时长。

1. POMO 在极小实例上的最优性差距

在每条路线 ≤ 10 个客户的实例上，POMO 的神经构造启发式产生次优路线（在 8-10 个客户实例上，与穷举枚举相比平均差距 +1,026%）。这是预期内的：POMO 在 CVRP-20/50/100 上训练，没有实现微实例上最优性的机制（穷举搜索在这些规模上可行）。对于需要微实例最优性保证的研究场景，应在阶段 2 中以精确求解器（如分支定价法）替代 POMO。

2. EV 充电作为后处理

充电决策在路径规划和时间调度全部完成后做出。这种顺序方法（路线 → 调度 → 充电）无法利用"不同路线可能减少总能耗足以完全避免充电"的机会。经验上成本惩罚较小（充电绕行额外增加 1.7-4.3% 的距离），但该方法在联合路径-充电问题上并非全局最优。

3. 无可动态或随机元素

该框架假设静态、确定性问题数据（已知客户位置、固定需求、已知 TW）。它不处理随机行驶时间、不确定需求或动态客户到达。扩展到随机 EVRP-TW 需要在滚动时域框架内重新运行流水线，或将不确定性纳入 POMO 训练分布。

4. Forward Insertion 依赖 POMO 的空间质量

Forward Insertion 是一个修复算子，而非构造算子。它只能修复已经从空间角度合理的路线中的延迟。若 POMO 产生了空间结构病态糟糕的路线（例如在城市中来回穿梭），FI 可能无法找到既能消除延迟又不导致其他位置不可行的前向位置，从而被迫回退到 EDD。经验上，POMO 的空间质量足够高，这种情况极少发生（回退率 < 3%），但该依赖是结构性的。

5. 单目标成本最小化

该框架最小化单一标量化成本（固定 + 距离）。它不产生成本与延迟、成本与车辆数量或成本与能耗之间的 Pareto 前沿。EVRP-TW 的多目标性质（冲突目标：更少的卡车 vs. 更短的距离 vs. 更少的充电次数）仅通过对多起点解进行事后 Pareto 提取来处理，而非通过显式的多目标优化。对于需要完整 Pareto 前沿的研究，NSGA-II 基线（尽管其 TW 不可行）或基于分解的 MOEA/D 方法会更合适。

定位声明

我们的分解框架在 EVRP-TW 求解器领域中占据了一个独特的位置：它提供了100% TW 可行性保证（如同精确方法），同时具有神经网络推理速度（不同于精确方法）。它不在 CEVRP 距离质量上与双层范式竞争（这些方法在该领域达到 SOTA），也不在最优性保证上与精确求解器竞争。其贡献在于使EVRP-TW 在实际操作中可求解 — 将一个所有经典方法均实现 0% 可行性的问题，转化为可在数秒内求解并具有保证 TW 合规性的问题。在 TW-CEVRP 基准上的 24:1 决定性结果凝结了这一贡献：现有范式中缺失的组成部分不是更好的路径规划或更好的充电策略，而是一个专门的 TW 修复机制。
