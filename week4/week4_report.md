## 1. Background

### 1.1 Week 3 Recap: The Metaheuristic Baseline

Week 3 established four methods on the 48-config EVRP-TW matrix:

| Method | Type | Mechanism | Strengths | Weaknesses |
|--------|------|-----------|-----------|------------|
| **No-Drone** | GA | Population evolution, PMX crossover | 100% feasible, fast | Truck-only, no drones |
| **P-ACO** | ACO | Dual pheromone matrices (cost + tardiness), collaborative ants | Good Pareto diversity at small scale | **13% feasible at 100c**, very slow (16 min/run) |

| **IVND** | Local Search | 7 neighborhood structures, simulated annealing, tabu list | Best Pareto quality | ~70% feasible at 100c |

All four share a common paradigm: **iterative improvement** — start from a (random or greedy) solution, then iteratively improve through neighborhood search or evolutionary operators.

### 1.2 POMO: A Fundamentally Different Paradigm

**POMO (Policy Optimization with Multiple Optima)** represents the **neural constructive** paradigm: a trained neural network directly builds the solution in one forward pass, without iteration.

#### 1.2.1 Core Algorithm

POMO is REINFORCE (policy gradient) with a key innovation — the **shared baseline** trick:

```
Standard REINFORCE:           POMO:
┌──────────────────┐          ┌──────────────────────────┐
│ π(a|s) → reward   │          │ π(a|s, start=node₁) → R₁  │
│        ↓          │          │ π(a|s, start=node₂) → R₂  │
│  ∇log π · (R - b) │          │ π(a|s, start=node₃) → R₃  │
│        ↓          │          │         ...               │
│  Update π         │          │ π(a|s, start=node_N) → R_N │
└──────────────────┘          │                           │
   Needs critic network       │ baseline = mean(R₁...R_N)  │
   for baseline b             │ ∇log π · (Rᵢ - baseline)    │
                              └──────────────────────────┘
                                No critic needed!
```

By starting N trajectories from N different first nodes and using their mean reward as a shared baseline, POMO achieves **low-variance gradient estimates without a separate value network**. The baseline is "free" — it comes from the multiple trajectories naturally generated by the problem structure.

#### 1.2.2 Architecture

```
Input: Node features (x, y, demand, ready_time, due_time, service_time) [N × 6]
       Depot position (x, y) [1 × 2]
       Context (remaining_capacity, current_time, battery) [3]
         │
    ┌────▼──────────────────────────────────────────┐
    │  Transformer Encoder (6 layers)                │
    │  ┌──────────────────────────────────────────┐ │
    │  │ Multi-Head Self-Attention (8 heads, 128D) │ │
    │  │   ↓ LayerNorm + Residual                   │ │
    │  │ Feed-Forward (512D)                        │ │
    │  │   ↓ LayerNorm + Residual                   │ │
    │  └──────────────────────────────────────────┘ │
    │  × 6 layers                                    │
    └────────────────────────────────────────────────┘
         │
    ┌────▼──────────────────────────────────────────┐
    │  Attention Decoder                             │
    │  ┌──────────────────────────────────────────┐ │
    │  │ Cross-Attention: context → encoder output  │ │
    │  │ Self-Attention: context → context          │ │
    │  │   ↓ LayerNorm + Residual                   │ │
    │  │ Linear → Softmax → action probabilities    │ │
    │  └──────────────────────────────────────────┘ │
    └────────────────────────────────────────────────┘
         │
         ▼
    P(next_customer | current_state) [N]
```

**Key architectural properties:**
- **Size-agnostic**: Transformer attention operates on sets — works for any N
- **Permutation equivariant**: Encoder output is invariant to input ordering
- **Context-aware**: Mask dynamically excludes visited nodes, capacity-violating nodes, and TW-violating nodes
- **1.6M parameters**: Small enough for CPU inference, large enough for expressive routing policies

#### 1.2.3 Training

| Phase | Details |
|-------|---------|
| **Pre-training** | CVRP on random uniform instances (N=50), minimizing total distance |
| **Transfer** | 54/80 encoder parameters transferred; decoder trained from scratch |
| **Fine-tuning** | 80 epochs, 400 episodes/epoch, batch_size=64 (32,000 batches) |
| **Problem generation** | Random N=50 instances, mixed tight/wide TW, uniform [0,16] coordinates |
| **Objective** | Weighted sum: **2.0 × distance + 1.0 × tardiness** |
| **Optimizer** | Adam, lr=1e-4, weight_decay=1e-6 |
| **Augmentation** | 8-fold dihedral group (×8 data via rotation/reflection) during training |

**The 2:1 cost:tardiness weight ratio is critical** — it explains POMO-MT's cost advantage and tardiness weakness. The model literally learns that 1 unit of distance saved is worth 2 units of tardiness incurred.

#### 1.2.4 Inference

At inference time, POMO uses **greedy argmax decoding** with **8-fold coordinate augmentation**:
1. Apply 8 dihedral transformations (4 rotations × 2 reflections) to the input coordinates
2. For each augmented view, run greedy argmax decoding
3. Collect all resulting routes, pick the best feasible one

This provides **deterministic diversity** — the same input always produces the same 8 candidates, and the same best route. This is fundamentally different from stochastic metaheuristics where each run produces different results.

### 1.3 Why Single-Route POMO Failed (Week 4 v1)

The first Week 4 attempt applied POMO directly: treat all N customers as one "giant CVRP" and let POMO output a single route. This failed catastrophically:

- **POMO outputs exactly one Hamiltonian cycle** — it cannot produce multi-vehicle solutions
- **A single truck cannot carry 540 units** of demand (capacity=200)
- **Result: 0% feasibility** — every solution violated capacity, time windows, or both

The diagnosis: POMO is a **single-vehicle router**. It needs **problem decomposition** to handle multiple vehicles.

## 2. POMO-MT: Cluster-First, Route-Second

### 2.1 Method Overview

```
Input: N customers, K trucks
  │
  ├─ Step 1: K-means clustering on (x, y) coordinates
  │     ├─ Auto-size: n_clusters = max(K, ceil(total_demand / 200))
  │     ├─ Lloyd's algorithm with k-means++ initialization (max 50 iterations)
  │     └─ Capacity balancing: greedy reassignment from overloaded → under-capacity
  │
  ├─ Step 2: For each cluster (size ≈ N / n_clusters):
  │     ├─ Build mini-instance with sub-distance matrix
  │     ├─ Preserve original customer IDs for solution reconstruction
  │     ├─ POMO inference: 8-fold coordinate augmentation → greedy argmax decoding
  │     └─ Extract best feasible route
  │
  └─ Output: Multi-truck solution (n_clusters truck routes, no drones)
```

This is a **cluster-first, route-second** heuristic — a classic VRP strategy (Fisher & Jaikumar, 1981), but with a **neural router** as the TSP solver instead of a classical heuristic (savings, sweep, etc.).

### 2.2 Why This Works: Problem Matching

The key insight is **matching the solver to the sub-problem**:

```
Original problem:                Decomposed:
┌─────────────────┐              ┌──────┐ ┌──────┐ ┌──────┐
│  N customers     │              │ 12c  │ │ 13c  │ │ 11c  │
│  K trucks        │  ──K-means──→ │ Truck│ │ Truck│ │ Truck│
│  Multi-vehicle   │              │  1   │ │  2   │ │  3   │
└─────────────────┘              └──────┘ └──────┘ └──────┘
    POMO can't solve                POMO CAN solve each!
    (single-route only)             (single-vehicle CVRP)
```

POMO was trained as a **single-vehicle CVRP solver**. The cluster-first decomposition creates exactly K single-vehicle CVRP sub-problems — each with ~N/K customers, well within the 200-unit capacity, and perfectly matching POMO's training distribution. This is essentially the **neural warm-start paradigm**: neural methods solve sub-problems, classical algorithms handle decomposition.

### 2.3 Clustering Details

**K-means (Lloyd's algorithm):**
- Initialization: k-means++ (probabilistic seeding proportional to squared distance)
- Distance metric: Euclidean on (x, y) coordinates
- Max iterations: 50 (typically converges in <10 for these instances)
- Auto-sizing: `n_clusters = max(n_trucks, ceil(total_demand / TRUCK_CAPACITY))`

**Capacity balancing:**
- Detect overloaded clusters (total demand > 200)
- Greedy reassignment: move nearest customer from overloaded → under-capacity cluster
- Up to 100 iterations (typically finishes in <5)

**Key limitation**: K-means uses **spatial-only distance**. Two customers at identical coordinates but with time windows 4 hours apart end up in the same cluster, guaranteeing high tardiness.

### 3.6 Deterministic Output: Feature or Bug?

A distinctive property of POMO-MT: **σ = 0 for all metrics**. All 10 repeats produce identical cost and tardiness. This is because:
1. K-means with fixed seed (k-means++ is deterministic given seed)
2. POMO greedy argmax → deterministic decoding
3. 8-fold augmentation → exhaustive deterministic enumeration

**Is this good or bad?**

| Advantage | Disadvantage |
|-----------|--------------|
| **Reproducible research** — exact same results every time | **No diversity** — cannot explore the Pareto front |
| **No seed tuning** — no "lucky runs" | **Cannot improve with more runs** — metaheuristics get better with more iterations |
| **Fast single-run** — one run is enough | **Single point on Pareto** — decision-maker sees only one trade-off |
| **Easy debugging** — deterministic behavior reveals bugs | **Brittle** — if the solution is bad, it's always bad |

This is a fundamental property of greedy neural decoding, not a bug. For applications needing a single fast solution, determinism is a feature. For multi-objective optimization needing a Pareto front, it's a severe limitation.

## 4. Analysis & Discussion

### 4.1 The Neural Constructive vs Iterative Improvement Paradigms

POMO-MT's results illuminate a deeper distinction between two optimization paradigms:

| Dimension | Neural Constructive (POMO-MT) | Iterative Improvement (Week 3) |
|-----------|------------------------------|-------------------------------|
| **How solutions are built** | One forward pass through NN | Thousands of incremental improvements |
| **Where intelligence lives** | In the trained weights (offline) | In the search strategy (online) |
| **Training cost** | High (hours of GPU, amortized) | Zero (no training needed) |
| **Inference cost** | Very low (milliseconds) | Moderate to high (seconds to minutes) |
| **Solution quality** | Depends on training data distribution | Depends on search budget |
| **Generalization** | Good (Transformer is size-agnostic) | Excellent (no learned bias) |
| **Pareto diversity** | 1 point (greedy) | 6–77 points (population/search) |
| **Constraint handling** | Learned (via mask) | Explicit (checked at each step) |
| **Interpretability** | Low (black box) | High (explicit operators) |

**The key trade-off**: POMO-MT amortizes training cost over many inference runs. If you need to solve 10,000 instances, POMO-MT's 0.65s/instance saves 2.7 hours vs No-Drone's 1s/instance. But if you need a high-quality Pareto front for one instance, Week 3's methods are superior.

### 4.2 Why POMO-MT Is So Much Cheaper (and Has So Much Tardiness)

Three reinforcing factors create POMO-MT's extreme cost-tardiness profile:

#### Factor 1: Training Objective Bias (Weight 2:1 Cost:Tardiness)

POMO's loss function:
```
L = E[(2.0 × total_distance + 1.0 × total_tardiness - baseline) × log π]
```

The model learns that **1 km of distance saved justifies 2 units of tardiness**. This ratio propagates through training:
- A route saving 10 km but incurring 19 tardiness → net "good" (2×10 > 1×19)
- The model systematically prefers shorter routes even at the cost of time window violations

This was a reasonable choice for CVRP pre-training (where no time windows exist), but it biases the fine-tuned model toward cost minimization.

#### Factor 2: Spatial-Only Clustering

K-means groups customers by (x, y) proximity. Consider this scenario:

```
Customer A: (2.0, 3.0), ready=0,   due=30   → morning delivery
Customer B: (2.1, 3.1), ready=200, due=230  → evening delivery
```

K-means puts both in the same cluster (nearly identical coordinates). A single truck must serve both — but they're 170+ time units apart. Either A is late (if B is served first) or the truck waits 170 units at B (if A is served first). Either way: **high tardiness**.

No-Drone's GA can put A and B on different trucks (or serve them with careful interleaving across routes), incurring extra distance but satisfying both time windows.

#### Factor 3: Greedy Decoding

POMO's argmax decoding always picks the single most-likely next node. There is no backtracking, no beam search, no exploration. If an early decision creates a suboptimal context (e.g., committing to a sequence that will inevitably cause tardiness), POMO cannot recover. Metaheuristics can undo bad decisions through mutation, shaking, and restart.

### 4.3 The Pareto Diversity Gap

The full Pareto plots reveal that POMO-MT produces **1 solution point** while other methods produce **3–77**. This is POMO-MT's most significant practical limitation:

- **Decision-makers see only one option** — no way to choose "pay 10% more cost for 50% less tardiness"
- **Cannot populate the Pareto front** — hypervolume comes entirely from the extreme cost advantage, not from diverse solutions
- **Fixed by sampling**: Replace greedy argmax with nucleus sampling (top-p) or temperature-controlled softmax → would produce diverse solutions at the cost of some quality

### 4.4 The Speed-Quality Frontier

![Runtime Comparison](visualizations/runtime_comparison.png)

Plotting methods on the speed-quality plane:

```
Quality (1/cost) ↑
    │
    │  ● POMO-MT               (best cost, fast)
    │
    │        ● No-Drone        (good cost, fast)
    │           ● IVND         (good all-around, moderate speed)
    │              ● NSGA-II   (balanced, moderate speed)
    │
    │                          ● P-ACO (good at small scale, extremely slow)
    │
    └──────────────────────────────────────────→ Speed (1/runtime)
```

POMO-MT occupies the **frontier corner**: best cost, fastest runtime. But this comes at the price of tardiness and Pareto diversity. For applications where:
- **Cost is paramount** (fuel-constrained operations) → POMO-MT is ideal
- **On-time delivery is critical** (perishable goods, JIT manufacturing) → IVND is better
- **Balanced optimization** is needed → NSGA-II or No-Drone

### 4.5 The Role of Transfer Learning

POMO-MT benefits from transfer learning in two ways:

1. **CVRP pre-training**: The encoder learns general spatial routing patterns from CVRP (Euclidean TSP-like problems). These patterns transfer to EVRP-TW because the spatial structure is identical.

2. **Size generalization**: Training on N=50 generalizes to clusters of 5–25 customers because the Transformer's self-attention is size-agnostic.

Without transfer learning, POMO would require:
- 2,000–5,000 epochs of EVRP-TW training (vs 80 epochs with transfer)
- More diverse training instances (varying N, TW types, depot positions)
- Potentially a larger model to learn both spatial and temporal constraints simultaneously

The transfer learning success suggests a broader principle: **pre-train on the simplest version of the problem, fine-tune on constraints**. CVRP is EVRP-TW without time windows, battery, or drones — and 54/80 encoder parameters transfer directly.

## 5. Conclusion

### 5.1 Achievements

| # | Achievement | Evidence |
|---|-------------|----------|
| 1 | **100% feasibility** across all 48 configs | Capacity-aware clustering + per-truck routing |
| 2 | **31–80% lower cost** than all Week 3 methods | Neural TSP-quality routing within clusters |
| 3 | **Fastest method** at all scales | 0.17–0.65s, single-pass neural inference |
| 4 | **Zero retraining** — reused 80-epoch checkpoint | Transfer learning from CVRP generalizes to EVRP-TW |
| 5 | **Fully reproducible** — deterministic output | σ = 0 for all metrics, exact scientific comparison |
| 6 | **Complete visualization suite** — 70 figures | Pareto plots, route maps, aggregate comparisons |

### 5.2 Limitations

| Limitation | Root Cause | Severity |
|-----------|------------|----------|
| **High tardiness** | Spatial-only K-means ignores time windows | Critical |
| **No Pareto diversity** | Greedy argmax produces single point | High |
| **Fleet-insensitive** | Auto-sizing ignores configured truck count | Moderate |
| **No drones** | By design (truck-only comparison) | By design |

### 5.3 Next Steps

1. **TW-aware clustering**: Replace Euclidean distance with spatio-temporal distance: `d(i,j) = α·spatial_dist(i,j) + β·temporal_gap(i,j)`. This directly addresses the tardiness problem.

2. **Stochastic POMO inference**: Replace greedy argmax with nucleus sampling or beam search to produce diverse Pareto points (1 → 10–50 points).

3. **Fine-tune for TW balance**: Retrain POMO with 1:1 or 1:2 cost:tardiness weight ratio to reduce the learned bias toward cost minimization.

4. **Drone post-processing**: After truck routes are fixed, insert drone missions greedily within each cluster to further reduce cost.

5. **Vehicle-count-aware clustering**: Produce exactly `n_trucks` clusters with capacity-respecting splits, enabling fair comparison with configured fleet sizes.

### 5.4 Broader Implications

POMO-MT validates the **neural warm-start paradigm**: neural methods excel at sub-problem solving (single-vehicle routing), while classical algorithms handle decomposition (clustering). This hybrid approach:

- **Plays to neural strengths** — single-vehicle routing matches POMO's training
- **Compensates for neural weaknesses** — POMO can't output multi-vehicle solutions
- **Preserves guarantees** — capacity feasibility is guaranteed by clustering, not the network
- **Is composable** — each component can be independently improved

This paradigm extends beyond vehicle routing to any constrained optimization where neural methods solve sub-problems while classical algorithms handle global constraints: job shop scheduling (NN per machine + dispatching rules), portfolio optimization (NN per asset + risk budgeting), facility location (NN per site + assignment algorithm).
